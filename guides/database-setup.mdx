CineFinder supports three database backends: **H2** (in-memory, for local development), **Oracle**, and **PostgreSQL**. Schema management is handled by [Flyway](https://flywaydb.org/), with separate migration paths for each database engine.

<Note>
  H2 is recommended for local development. It requires no external database server and seeds sample data automatically on startup.
</Note>

## How migrations are organised

Flyway migration scripts live under two paths in `src/main/resources/`:

```
db/migration/
├── h2/
│   ├── V1__create_tables.sql   # Schema creation
│   └── V2__insert_data.sql     # Seed data (movies, users, reviews)
└── oracle/
    ├── V2__create_tables.sql   # Schema creation
    └── V3__insert_mock_data.sql
```

The active migration path is selected by the `spring.flyway.locations` property, which changes between profiles.

## H2 (development)

<Tabs>
  <Tab title="Run command">
    Activate the `dev` Spring profile when starting the application:

    ```bash
    ./gradlew bootRun --args='--spring.profiles.active=dev'
    ```
  </Tab>
  <Tab title="application.yaml (dev profile)">
    The `dev` profile block is already included in `application.yaml`:

    ```yaml
    spring:
      config:
        activate:
          on-profile: dev

      datasource:
        url: jdbc:h2:mem:cinefinder;MODE=Oracle
        driver-class-name: org.h2.Driver
        username: sa
        password:

      jpa:
        database-platform: org.hibernate.dialect.H2Dialect
        hibernate:
          ddl-auto: none
        show-sql: true

      flyway:
        enabled: true
        baseline-on-migrate: true
        locations: classpath:db/migration/h2
    ```
  </Tab>
</Tabs>

H2 runs in **Oracle compatibility mode** (`MODE=Oracle`) so SQL written for Oracle executes without modification. No configuration is required beyond activating the profile — Flyway applies `V1__create_tables.sql` then `V2__insert_data.sql` automatically, populating the database with sample movies, users, and reviews.

## Oracle (production)

Replace the default datasource block in `application.yaml` with your Oracle connection details:

```yaml
spring:
  datasource:
    url: jdbc:oracle:thin:@<host>:1521:ORCL
    username: <username>
    password: <password>
    driver-class-name: oracle.jdbc.OracleDriver

  jpa:
    database-platform: org.hibernate.dialect.OracleDialect
    hibernate:
      ddl-auto: validate

  flyway:
    enabled: true
    baseline-on-migrate: true
    locations: classpath:db/migration/oracle
```

The Oracle JDBC driver (`ojdbc11`) is declared as a `runtimeOnly` dependency in `build.gradle` and is included automatically. Flyway will apply `V2__create_tables.sql` followed by `V3__insert_mock_data.sql`.

<Warning>
  Do not commit real credentials to source control. Use environment variables or a secrets manager to inject `spring.datasource.username` and `spring.datasource.password` at runtime.
</Warning>

## PostgreSQL

PostgreSQL support is included via the `org.postgresql:postgresql` runtime dependency and the `org.flywaydb:flyway-database-postgresql` Flyway module, both already declared in `build.gradle`.

```yaml
spring:
  datasource:
    url: jdbc:postgresql://<host>:5432/<database>
    username: <username>
    password: <password>
    driver-class-name: org.postgresql.Driver

  jpa:
    database-platform: org.hibernate.dialect.PostgreSQLDialect
    hibernate:
      ddl-auto: validate

  flyway:
    enabled: true
    baseline-on-migrate: true
    locations: classpath:db/migration/oracle
```

The Oracle migration scripts use standard SQL that is broadly compatible with PostgreSQL. If you encounter dialect-specific issues, create a dedicated `db/migration/postgresql/` directory and point `spring.flyway.locations` at it.

## Database schema

The following tables are created by the migration scripts.

### `cf_user`

Stores registered users.

| Column | Type | Notes |
|--------|------|-------|
| `id` | `BIGINT` / `NUMBER` | Primary key, auto-generated |
| `name` | `VARCHAR(255)` | Display name |
| `email` | `VARCHAR(255)` | Used for authentication |
| `password` | `VARCHAR(255)` | BCrypt-hashed |
| `age` | `INT` / `NUMBER(3)` | Must be ≥ 18 to register |
| `is_admin` | `BOOLEAN` / `NUMBER(1)` | `1` = admin role |

### `cf_movie`

Stores movie catalogue entries.

| Column | Type | Notes |
|--------|------|-------|
| `id` | `BIGINT` / `NUMBER` | Primary key, auto-generated |
| `title` | `VARCHAR(255)` | |
| `description` | `VARCHAR(255)` | |
| `release_date` | `DATE` | |
| `average_rating` | `DECIMAL(4,2)` / `NUMBER(4,2)` | Recomputed on each new review |
| `poster_url` | `VARCHAR(500)` | Absolute URL to poster image |

### `cf_movie_genres`

Join table linking movies to their genres (stored as enum strings, e.g. `SCI_FI`, `ACTION`, `DRAMA`, `ADVENTURE`).

| Column | Type | Notes |
|--------|------|-------|
| `movie_id` | `BIGINT` / `NUMBER` | FK → `cf_movie.id` |
| `genre` | `VARCHAR(255)` | Enum value |

### `cf_review`

Stores user reviews for movies.

| Column | Type | Notes |
|--------|------|-------|
| `id` | `BIGINT` / `NUMBER` | Primary key, auto-generated |
| `user_id` | `BIGINT` / `NUMBER` | FK → `cf_user.id` |
| `movie_id` | `BIGINT` / `NUMBER` | FK → `cf_movie.id` |
| `rating` | `DECIMAL(4,2)` / `NUMBER(4,2)` | Contributes to `average_rating` |
| `comments` | `VARCHAR(255)` | |

### `cf_movie_list`

Named lists of movies owned by a user.

| Column | Type | Notes |
|--------|------|-------|
| `id` | `BIGINT` / `NUMBER` | Primary key, auto-generated |
| `name` | `VARCHAR(255)` | List display name |
| `user_id` | `BIGINT` / `NUMBER` | FK → `cf_user.id` |

### `cf_movie_list_movies`

Join table linking movies to movie lists.

| Column | Type | Notes |
|--------|------|-------|
| `movie_id` | `BIGINT` / `NUMBER` | FK → `cf_movie.id` |
| `movie_list_id` | `BIGINT` / `NUMBER` | FK → `cf_movie_list.id` |
